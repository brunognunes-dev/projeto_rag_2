▶ Fase 1 — Indexação (Caminho de Ida)
1
INGESTÃO / OCR
Leitura dos documentos PDF e extração de texto via OCR
Documentos fonte processados pelo PdfReader 3 PDFs
📋 pypdf.PdfReader → extract_text() → texto bruto por página
texto extraído
2
TOKENIZAÇÃO
Divisão do texto bruto em tokens individuais (unidades léxicas)
Tokens gerados a partir do texto do documento ~42 tokens
🔤 text.split() → cada palavra/subpalvra vira um token individual
agrupamento
3
CHUNKING
Agrupamento dos tokens em blocos (chunks) de ~200 caracteres para contexto semântico
Chunks formados (janelas semânticas do documento) 3 chunks
🧩 chunk_size ≥ 200 chars → agrupar linhas → novo chunk
vetorização
4
EMBEDDING (Vetorização)
Cada chunk é convertido em um vetor numérico de 384 dimensões via FastEmbed (BAAI/bge-small-en-v1.5)
Vetores de representação semântica de cada chunk 384 dimensões
🧮 FastEmbed.embed(chunk_text) → vetor float[384] — captura o significado semântico
armazenamento
5
ÍNDICE VETORIAL (PGVECTOR)
Vetores armazenados no Supabase com PGVECTOR para busca por similaridade cosseno
Registros armazenados na tabela rag_documents Supabase PGVECTOR
🗄️ INSERT INTO rag_documents (document_name, chunk_index, content, metadata, embedding)
◀ Fase 2 — Consulta (Caminho Inverso)
Q1
PERGUNTA DO USUÁRIO
A pergunta em linguagem natural inicia o caminho inverso do RAG
Pergunta recebida
"Qual foi o valor total da nota fiscal da TechSupply Brasil?"
tokenizar query
Q2
TOKENIZAÇÃO DA QUERY
A pergunta do usuário é quebrada nos mesmos tokens usados na indexação
Tokens da pergunta do usuário ~12 tokens
embedding da query
Q3
EMBEDDING DA QUERY
A pergunta tokenizada é convertida em vetor 384d pelo mesmo modelo FastEmbed
Vetor da pergunta (mesmo espaço vetorial dos chunks) float[384]
🧮 embedding_service.generate_embedding(question) → vetor no mesmo espaço dos documentos
busca cosine similarity
Q4
RETRIEVAL (Top-K Similaridade Cosseno)
O vetor da query é comparado com todos os vetores armazenados. Os 5 mais similares são retornados.
Candidatos ranqueados por similaridade (threshold ≥ 0.25) Top 5 candidatos
📐 score = cos(q⃗, d⃗) = (q⃗ · d⃗) / (‖q⃗‖ × ‖d⃗‖) — quanto mais próximo de 1.0, mais relevante
construção do prompt
Q5
PROMPT AUMENTADO (Augmented Prompt)
O contexto recuperado é combinado com a pergunta para construir o prompt final enviado ao LLM
Prompt enviado ao LLM
📝 Prompt = System Instruction + Contexto Recuperado (Chunks relevantes) + Pergunta do Usuário
geração LLM
Q6
RESPOSTA DO LLM
O modelo de linguagem (OpenRouter) gera a resposta final com base exclusivamente no contexto fornecido
OpenRouter — LLM Response
🤖 O LLM responde EXCLUSIVAMENTE com base no contexto recuperado. Se não houver dados → "Sem dados disponíveis na base"
